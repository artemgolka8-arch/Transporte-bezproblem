# FLEET/OS — учёт транспорта

Мини-сайт для учёта велосипедов и самокатов: статусы (доступен / в мастерской / в аренде),
описание проблем, история изменений и панель ключей (батарея A, батарея B, замок, дубликаты)
для каждой единицы техники. Доступ по логину, три роли: администратор, менеджер, наблюдатель.

Стек: Next.js 14 (App Router) + TypeScript + Tailwind CSS + Prisma + PostgreSQL + NextAuth.

---

## 1. Локальный запуск

Понадобится Node.js 18+ и доступ к PostgreSQL (локально, в Docker, или сразу через Railway — см. ниже).

```bash
cd fleet-manager
npm install
cp .env.example .env
```

Откройте `.env` и укажите:
- `DATABASE_URL` — строка подключения к вашей PostgreSQL
- `NEXTAUTH_SECRET` — случайная строка (можно сгенерировать: `openssl rand -base64 32`)
- `SEED_ADMIN_EMAIL` / `SEED_ADMIN_PASSWORD` — логин и пароль первого администратора

Создайте таблицы и первого администратора:

```bash
npx prisma db push
npm run seed
```

Запустите сайт:

```bash
npm run dev
```

Откройте http://localhost:3000 и войдите под данными администратора, которые вы указали в `.env`.

## 3. Деплой на Railway

1. Зайдите на [railway.app](https://railway.app) → **New Project** → **Deploy from GitHub repo** → выберите ваш репозиторий.
2. В этом же проекте нажмите **+ New** → **Database** → **Add PostgreSQL**. Railway создаст базу и переменную `DATABASE_URL` внутри своего окружения.
3. Откройте сервис с сайтом (не базу) → вкладка **Variables** → добавьте:
   - `DATABASE_URL` → нажмите "Add Reference" и выберите `DATABASE_URL` от сервиса Postgres (Railway подставит ссылку сам)
   - `NEXTAUTH_SECRET` → любая длинная случайная строка
   - `NEXTAUTH_URL` → публичный адрес вашего сервиса, например `https://ваш-проект.up.railway.app` (можно добавить после первого деплоя, когда Railway выдаст домен, и передеплоить)
   - `SEED_ADMIN_EMAIL`, `SEED_ADMIN_PASSWORD`, `SEED_ADMIN_NAME` — данные администратора
4. Railway автоматически определит Next.js проект и соберёт его (`npm install`, затем `npm run build`). При старте (`npm start`) схема базы синхронизируется автоматически (`prisma db push`).
5. Чтобы создать первого администратора в облачной базе, один раз выполните сид через Railway:
   - вкладка сервиса → **Settings** → **Deploy Triggers**, либо проще — через Railway CLI:
     ```bash
     npm i -g @railway/cli
     railway login
     railway link
     railway run npm run seed
     ```
6. Откройте домен, который выдал Railway (**Settings → Networking → Generate Domain**), и войдите под администратором.

После этого администратор может создавать менеджеров и наблюдателей прямо в интерфейсе, во вкладке «Пользователи».

## Роли доступа

| Роль | Может |
|---|---|
| **Администратор** | всё: техника, ключи, статусы, управление пользователями |
| **Менеджер** | добавлять/редактировать технику, менять статусы, вести ключи |
| **Наблюдатель** | только просматривать флот, статусы и ключи |

## Структура данных

- **Vehicle** — единица техники: код, название, тип (велосипед/самокат), статус, описание проблемы, локация/арендатор
- **Key** — ключ, привязанный к технике: название («Ключ от батареи A»), пометка «дубликат», место хранения
- **StatusLog** — история изменений статуса с автором и временем
- **User** — пользователь с ролью
- **Task** — задача: название, описание, срок, напоминание, статус (в работе/выполнена), автор и исполнитель
- **TaskLog** — история задачи: создание, выполнение, возврат в работу, передача другому

## 4. Напоминания о задачах в Telegram

Во вкладке «Задачи» при создании можно указать дату и время напоминания. В нужный момент
бот пришлёт сообщение в Telegram исполнителю задачи.

### 4.1 Создать бота

1. В Telegram откройте [@BotFather](https://t.me/BotFather), отправьте `/newbot` и следуйте инструкциям.
2. Получите токен вида `123456789:AAExxxxxxxxxxxxxxxxxxxxxxxxxxxxx` — это `TELEGRAM_BOT_TOKEN`.
3. Отправьте боту (можно себе, для проверки) `/start` — Telegram разрешает ботам писать только тем,
   кто сам первым написал боту. Каждый сотрудник, который хочет получать напоминания, должен
   один раз найти вашего бота и нажать «Start».

### 4.2 Узнать свой Chat ID

Каждый пользователь узнаёт свой числовой Telegram ID (например, через
[@userinfobot](https://t.me/userinfobot) — просто напишите ему) и вставляет это число в
поле «Telegram Chat ID» на странице «Профиль». Подробная подсказка есть прямо в интерфейсе.

### 4.3 Настроить переменные окружения

В `.env` (или в переменных сервиса на Railway) добавьте:
- `TELEGRAM_BOT_TOKEN` — токен из BotFather
- `CRON_SECRET` — любая случайная строка, ей защищён эндпойнт рассылки

### 4.4 Настроить расписание проверки

Приложение само ничего не отправляет по таймеру — нужен внешний планировщик, который раз в
минуту (или в 5 минут) дёргает `GET /api/tasks/reminders/run?secret=ВАШ_CRON_SECRET`.
Варианты:

**Railway Cron Job** (проще всего, если сайт уже на Railway):
1. В том же проекте Railway → **+ New** → **Cron Job**.
2. Command: `curl -fsS "https://ВАШ-ДОМЕН.up.railway.app/api/tasks/reminders/run?secret=ВАШ_CRON_SECRET"`
3. Schedule: `* * * * *` (каждую минуту) или `*/5 * * * *` (раз в 5 минут).

**Бесплатный внешний сервис** (если не хочется платить за отдельный Railway-сервис):
[cron-job.org](https://cron-job.org) → создайте задачу на URL
`https://ВАШ-ДОМЕН.up.railway.app/api/tasks/reminders/run?secret=ВАШ_CRON_SECRET`,
интервал — 1 минута.

Без секрета эндпойнт отвечает `401` — никто посторонний рассылку не запустит.

## 5. Раздел «Должники» (синхронизация с ravapi.eu)

Вкладка «Должники» показывает список клиентов с задолженностью, полученный из
кабинета `portal.ravapi.eu`. Данные не подтягиваются автоматически по таймеру —
только по нажатию кнопки «Обновить» на самой странице (её видят роли
администратор и менеджер).

### 5.1 Настроить переменные окружения

В `.env` (или в Variables на Railway) добавьте:
- `RAVAPI_EMAIL` — email вашего аккаунта в ravapi.eu
- `RAVAPI_PASSWORD` — пароль от этого аккаунта

Приложение использует их только на сервере: при нажатии «Обновить» сервер сам
логинится в ravapi.eu, получает список должников и сохраняет его в вашей базе
(таблица `Debtor`). Пароль в браузер пользователя никогда не попадает.

### 5.2 Важно про безопасность

- Используйте для `RAVAPI_EMAIL`/`RAVAPI_PASSWORD` отдельный аккаунт с
  минимально необходимыми правами в ravapi.eu, если такая возможность есть у
  них в системе.
- Если логин/пароль от ravapi.eu когда-либо публиковались (например, случайно
  попали в переписку, скриншот, чат с ассистентом) — обязательно смените
  пароль в личном кабинете ravapi.eu.
- `.env` в репозиторий не попадает (см. `.gitignore`), но не публикуйте его
  содержимое нигде ещё.

### 5.3 Как это устроено технически

Кабинет `portal.ravapi.eu` — это SPA без официального публичного API. Раздел
«Должники» пользуется их внутренним (недокументированным) эндпойнтом
`POST /api/Drivers/GetDebtors`, к которому сервер получает доступ, предварительно
залогинившись через `POST /api/login` и переиспользуя выданные cookie. Логика —
в `src/lib/ravapi.ts`. Так как это не публичный API, ravapi.eu может в любой
момент изменить формат ответа или структуру логина без предупреждения — в этом
случае синхронизация начнёт возвращать ошибку, и её нужно будет поправить под
новую структуру (проще всего — заново посмотреть в DevTools → Network, как
изменился запрос).
