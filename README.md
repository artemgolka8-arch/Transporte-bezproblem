# FLEET/OS — учёт транспорта

Мини-сайт для учёта велосипедов и самокатов: статусы (доступен / в мастерской / в аренде),
описание проблем, история изменений и панель ключей (батарея A, батарея B, замок, дубликаты)
для каждой единицы техники. Доступ по логину, три роли: администратор, менеджер, наблюдатель.

Стек: Next.js 14 (App Router) + TypeScript + Tailwind CSS + Prisma + PostgreSQL + NextAuth.

---

## 1. Локальный запуск

Понадобится Node.js 18+ и доступ к PostgreSQL (локально, в Docker, или сразу через Railway — см. ниже).

```bash
cd fleet-manager
npm install
cp .env.example .env
```

Откройте `.env` и укажите:
- `DATABASE_URL` — строка подключения к вашей PostgreSQL
- `NEXTAUTH_SECRET` — случайная строка (можно сгенерировать: `openssl rand -base64 32`)
- `SEED_ADMIN_EMAIL` / `SEED_ADMIN_PASSWORD` — логин и пароль первого администратора

Создайте таблицы и первого администратора:

```bash
npx prisma db push
npm run seed
```

Запустите сайт:

```bash
npm run dev
```

Откройте http://localhost:3000 и войдите под данными администратора, которые вы указали в `.env`.

## 2. Публикация на GitHub

```bash
cd fleet-manager
git init
git add .
git commit -m "Fleet manager: первая версия"
```

Создайте пустой репозиторий на github.com (без README/лицензии), затем:

```bash
git remote add origin https://github.com/ВАШ_АККАУНТ/ВАШ_РЕПОЗИТОРИЙ.git
git branch -M main
git push -u origin main
```

Файл `.env` в репозиторий не попадёт — он в `.gitignore` намеренно, чтобы пароли не утекли.

## 3. Деплой на Railway

1. Зайдите на [railway.app](https://railway.app) → **New Project** → **Deploy from GitHub repo** → выберите ваш репозиторий.
2. В этом же проекте нажмите **+ New** → **Database** → **Add PostgreSQL**. Railway создаст базу и переменную `DATABASE_URL` внутри своего окружения.
3. Откройте сервис с сайтом (не базу) → вкладка **Variables** → добавьте:
   - `DATABASE_URL` → нажмите "Add Reference" и выберите `DATABASE_URL` от сервиса Postgres (Railway подставит ссылку сам)
   - `NEXTAUTH_SECRET` → любая длинная случайная строка
   - `NEXTAUTH_URL` → публичный адрес вашего сервиса, например `https://ваш-проект.up.railway.app` (можно добавить после первого деплоя, когда Railway выдаст домен, и передеплоить)
   - `SEED_ADMIN_EMAIL`, `SEED_ADMIN_PASSWORD`, `SEED_ADMIN_NAME` — данные администратора
4. Railway автоматически определит Next.js проект и соберёт его (`npm install`, затем `npm run build`). При старте (`npm start`) схема базы синхронизируется автоматически (`prisma db push`).
5. Чтобы создать первого администратора в облачной базе, один раз выполните сид через Railway:
   - вкладка сервиса → **Settings** → **Deploy Triggers**, либо проще — через Railway CLI:
     ```bash
     npm i -g @railway/cli
     railway login
     railway link
     railway run npm run seed
     ```
6. Откройте домен, который выдал Railway (**Settings → Networking → Generate Domain**), и войдите под администратором.

После этого администратор может создавать менеджеров и наблюдателей прямо в интерфейсе, во вкладке «Пользователи».

## Роли доступа

| Роль | Может |
|---|---|
| **Администратор** | всё: техника, ключи, статусы, управление пользователями |
| **Менеджер** | добавлять/редактировать технику, менять статусы, вести ключи |
| **Наблюдатель** | только просматривать флот, статусы и ключи |

## Структура данных

- **Vehicle** — единица техники: код, название, тип (велосипед/самокат), статус, описание проблемы, локация/арендатор
- **Key** — ключ, привязанный к технике: название («Ключ от батареи A»), пометка «дубликат», место хранения
- **StatusLog** — история изменений статуса с автором и временем
- **User** — пользователь с ролью
