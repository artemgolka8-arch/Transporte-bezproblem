# Отчёты: кнопка «Добавить план» и проверка планов

Во вкладке «Отчёты» рядом с «Новый отчёт» появилась кнопка **«Добавить план»**,
а под заголовком — переключатель **«Отчёты | Планы»** (у проверяющих на вкладках
виден счётчик планов и отчётов, ожидающих проверки).

**Что пишет амбассадор:** описание планов, **дату**, на которую построен план
(по умолчанию — завтра) и **сколько часов** планирует работать (0,5–24).
Описание до 3000 символов, поле растягивается; есть счётчик символов.

**Просмотр плана:** окно с ограниченной высотой и заметным ползунком — длинный
план листается целиком, шапка и кнопки остаются на месте.

**Проверка (PR-менеджер, директор, администратор; свой план проверять нельзя):**
- **Подтвердить** — план утверждён;
- **Не подтвердить** — обязательно описать причину и что нужно исправить;
- **Добавить** — проверяющий вносит предложение, что изменить или добавить в плане
  (статус «Есть дополнения»).

**Автор** видит статус и комментарий проверяющего. Если план не подтверждён или к нему
есть предложения — кнопка **«Исправить план»**: форма открывается с заполненными данными,
после «Отправить на проверку заново» план снова получает статус «На проверке».
Амбассадор видит только свои планы, остальные роли — все. Удалить план может автор,
администратор и PR-менеджер. Все проверки прав дублируются на сервере.

```

src/lib/plans.ts                           — типы, toPlanRow, проверка данных плана (новый)
src/lib/roles.ts                           — путь /api/plans разрешён ограниченным ролям
src/app/api/plans/route.ts                 — GET, POST (новый)
src/app/api/plans/[id]/route.ts            — PATCH (исправление автором), DELETE (новый)
src/app/api/plans/[id]/review/route.ts     — POST: подтвердить / не подтвердить / добавить (новый)

# Отчёты: просмотр с прокруткой + проверка отчётов (подтвердить / не подтвердить)

## 1. Ползунок при просмотре отчёта
Окно отчёта теперь ограничено по высоте экрана, а содержимое прокручивается
внутри него с заметным ползунком — длинный отчёт можно пролистать целиком.
Шапка (автор, дата, статус) и нижняя панель с кнопками остаются на месте.
Форма «Новый отчёт» тоже исправлена: на маленьких экранах её верх больше не обрезается.

## 2. Проверка отчётов
- **Кто проверяет:** PR-менеджер, директор, администратор (`canReviewReports`
  в `src/lib/roles.ts`). Свой отчёт проверять нельзя.
- В окне отчёта у проверяющих две кнопки: **«Подтвердить»** и **«Не подтвердить»**.
  «Не подтвердить» открывает поле «Что не так и что нужно изменить» —
  комментарий обязателен. Решение можно изменить позже.
- В таблице новая колонка «Проверка» (на проверке / подтверждён / не подтверждён)
  и фильтр-вкладки со счётчиками над таблицей.
- Автор видит статус своего отчёта и замечание. Если отчёт не подтверждён —
  кнопка **«Исправить отчёт»**: форма открывается с заполненными данными,
  после «Отправить на проверку заново» отчёт снова получает статус «На проверке».
- Все проверки прав дублируются на сервере.
- Уже существующие отчёты получат статус «На проверке».

```

src/app/api/reports/route.ts                — POST через общую проверку
src/app/api/reports/[id]/route.ts           — PATCH: автор исправляет не подтверждённый отчёт

# Новая вкладка «Зарплаты и бонусы» (только директор и администратор)

Учёт выплат сотрудникам: кому, сколько, каким способом и за что выдали.

**Что есть на странице**
- Кнопка «Новая выплата» → окно: получатель (выбор из сотрудников или «Другой
  получатель…» вручную), тип (зарплата / бонус / аванс / другое), сумма в zł,
  дата, способ выдачи (**на счёт / на карту / наличные**), **номер счёта**
  (обязателен для «На счёт», для карты — по желанию, для наличных не нужен),
  описание «за что выдано».
- Карточки-итоги: всего выдано, зарплаты, бонусы, наличными (с долей от суммы).
  Считаются за выбранный период («за всё время», «этот месяц» или любой месяц).
- Фильтры: поиск (имя, описание, номер счёта), тип, способ, месяц.
- Таблица с аватарками получателей, цветными бейджами типа, суммой, способом
  и номером счёта, описанием и датой. Клик по строке — редактирование
  (там же кнопка «Удалить»). Внизу — количество и сумма по текущему фильтру.
- Тексты на русском, польском и украинском.

**Доступ — только ADMIN и DIRECTOR**
- Пункт меню показывается только им.
- Закрыто в трёх местах: `middleware.ts` (страница → редирект, API → 403),
  сама страница `/payroll` и все обработчики `/api/payroll*`. Менеджер,
  PR-менеджер, амбассадор и наблюдатель не увидят и не откроют раздел даже
  по прямой ссылке.

# «Моя команда»: аватарки, просмотр профилей, должность — только директор/админ

1. **Аватарки в списке.** В «Моей команде» у каждого сотрудника показывается его
   фото (если нет — инициалы). Фото отдаётся отдельным маршрутом
   `/api/team/[id]/avatar` и кэшируется браузером — HTML страницы не раздувается.
2. **Просмотр профиля друг друга.** Клик по любому сотруднику открывает его
   профиль `/team/[id]` (свой — как раньше ведёт в «Профиль»). Это только
   просмотр: фото, роль, почта, телефон, город, должность. Telegram Chat ID
   другим не показывается.
3. **Кто что может менять.**
   - Чужие данные не может менять никто.
   - **Должность** могут менять только **директор и администратор** — в чужом
     профиле (кнопка «Сохранить» рядом с полем) и в своём. У остальных ролей
     поле «Должность» в собственном профиле стало только для чтения.
   - Проверка есть и на сервере (`PATCH /api/team/[id]`, `PATCH /api/profile`),
     а не только в интерфейсе.
   - Остальные свои данные (имя, телефон, город, Telegram, фото) каждый по-прежнему
     меняет у себя в «Профиле».

# Роль «PR Manager» + новые права в вкладке «Задачи»

## Что нового

1. **Новая роль `PR_MANAGER`** — выбирается при создании/редактировании
   аккаунта (страница «Пользователи», доступна ADMIN). По правам — как
   MANAGER, но дополнительно умеет ставить задачи.

2. **PR Manager может ставить задачи**: Амбассадорам, другим PR-менеджерам,
   Администраторам и Директору (раньше исполнителем мог быть только
   ADMIN/MANAGER). Список «Кому поставить задачу» на странице `/tasks`
   теперь включает все эти роли.

3. **Амбассадор и Директор получили доступ к вкладке «Задачи»**
   (`/tasks`) — раньше им был доступен только раздел «Приглашённые
   клиенты», «Отчёты», «Моя команда» и профиль.

4. **Для Амбассадора вкладка «Задачи» урезана**: только просмотр своих
   задач + две кнопки — «Выполнено» и «Не выполнено». Кнопок «Передать»
   и «Удалить» амбассадор не видит (и не может выполнить эти действия
   через API — проверено и на сервере, не только в интерфейсе).

5. **«Не выполнено» требует обязательной причины**: при нажатии
   открывается модальное окно с текстовым полем — без заполнения
   отправить нельзя (ни на клиенте, ни на сервере: `POST` без `note`
   вернёт ошибку 400 «Укажите причину невыполнения»). Причина сохраняется
   в `Task.notDoneReason` и отображается прямо на карточке задачи
   (плюс попадает в историю изменений).

6. Задача в статусе «Не выполнено» — отдельный статус (`NOT_DONE`, кроме
   `OPEN`/`DONE`), с красным бейджем. В фильтре «В работе» такие задачи
   тоже показываются (это ещё не завершённые успешно задачи).

## Как это работает по ролям

- **ADMIN / MANAGER** — без изменений, полный доступ к задачам (как раньше).
- **PR_MANAGER** — то же самое, что MANAGER, + видит вкладку «Задачи» и
  может назначать её на Ambassador/PR_MANAGER/ADMIN/DIRECTOR.
- **DIRECTOR** — получил доступ к «Задачам» (может выполнять полный набор
  действий над своими задачами: выполнено/не выполнено/передать/удалить,
  как обычный участник задачи — создавать новые задачи по-прежнему нельзя).
- **AMBASSADOR** — получил доступ к «Задачам» в урезанном виде: видит
  только свои задачи, отмечает «выполнено» / «не выполнено» (с обязательной
  причиной), не может создавать, передавать или удалять задачи.

## Как применить

Скопируйте файлы поверх соответствующих путей в вашем репозитории
